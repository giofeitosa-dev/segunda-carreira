## Fluxo de exclusão (US1)

1. `DELETE /api/v1/meus-dados` → `TitularController.excluir(usuarioId)` → `PerfilService.excluirTitular(usuarioId)`
2. Busca `Usuario` por id; se não houver perfil → 200 (idempotente)
3. Se houver perfil → `perfilRepository.delete(perfil)` (cascade remove experiencias, formacoes, projetos, idiomas, certificacoes, perfil_competencia, inscricoes via orphanRemoval)
4. `usuario.setPerfil(null)` → `usuarioRepository.save(usuario)` (desvincula) ou `usuarioRepository.delete(usuario)`
5. `auditoria_seguranca` mantém registros com `usuario_id` preenchido (SET NULL já definido na V3)

## Fluxo de exportação (US2)

1. `GET /api/v1/meus-dados/exportacao` → `TitularController.exportar(usuarioId)` → `PerfilService.exportarTitular(usuarioId)`
2. Busca `Usuario` por id; monta `DadosTitularResponse` com dados do perfil e filhas
3. Retorna JSON sem senha

## Migração V4__lgpd_governance.sql

```sql
-- Flyway V4: configuração de retenção LGPD (ciclo 003)
-- Tabela opcional para armazenar políticas de retenção por tipo de dado

CREATE TABLE IF NOT EXISTS configuracao_retencao (
    id BIGINT NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    tipo_dado VARCHAR(100) NOT NULL,
    dias_retencao INTEGER NOT NULL,
    ativo BOOLEAN NOT NULL DEFAULT TRUE,
    criado_em TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT pk_configuracao_retencao PRIMARY KEY (id),
    CONSTRAINT uk_configuracao_retencao_tipo UNIQUE (tipo_dado)
);

-- Registro padrão: perfil retido por 365 dias de inatividade
INSERT INTO configuracao_retencao (tipo_dado, dias_retencao, ativo)
VALUES ('perfil', 365, TRUE)
ON CONFLICT (tipo_dado) DO NOTHING;

-- Auditoria é imutável: sem retenção (não entra na purga)
INSERT INTO configuracao_retencao (tipo_dado, dias_retencao, ativo)
VALUES ('auditoria_seguranca', 0, FALSE)
ON CONFLICT (tipo_dado) DO NOTHING;
```
